EXECUTIVE SUMMARY
--------------------------------------------------------------------------------

Dream v3.0 (Phase 6) turned Dream into a world ecologist: it designs the
space, the creatures, the pacing, and the boss. But every gift Phase 5.5 and
Phase 6 gave to creativity is a debt collected from the frame budget:

  - 50 unique L-System trees  =  50 geometry generations = 50 draw calls
  - 20 mutated enemies        =  20 full anatomy syntheses
  - Curvature-aware collision =  thousands of capsules checked per entity
  - 13-enemy boss waves       =  13 instantiations at the worst possible
                                 moment (wave start)

The rule of Phase 7 is simple and non-negotiable:

    A MAP THAT SCORES 95/100 ON FLOW BUT RENDERS AT 15 FPS SCORES ZERO.

Dream cannot just be an Architect anymore. It must become a Performance
Engineer. Phase 7 teaches Dream to count — triangles, draw calls, capsules,
milliseconds — and it teaches the RUNTIME to survive whatever Dream builds.

THE PRIME DIRECTIVE (HOUSE RULES ARE SACRED)
--------------------------------------------------------------------------------

Every system in this document must pass the existing performance-optimizer
specification unchanged:

  1. ZERO-ALLOCATION GAME LOOP. No `new THREE.Vector3()`, no object literals,
     no closures created inside tick(). Every Phase 7 runtime system uses
     preallocated ring buffers, pooled lists, and borrowed references.
  2. SINGLE-PASS POST-PROCESSING. The ballpoint composite (halftone, hatch,
     outline) remains ONE pass. Phase 7 adds quality knobs to that pass —
     never additional passes.
  3. PIXEL RATIO CAP. Math.min(window.devicePixelRatio || 1, 2.0) remains
     the ceiling; Tier profiles may lower it, nothing may raise it.

If a proposed optimization violates any of these, it is rejected by design.

NAMING NOTE (AVOIDING A COLLISION)
--------------------------------------------------------------------------------

The Dream PIPELINE already ends with "Phase 7: Learning & Export." To avoid
confusion, this development phase ("Dream Phase 7") implements a NEW pipeline
step inserted between Ecosystem Inhabitants and Learning & Export:

    PIPELINE STEP 6.5: THE OPTIMIZATION PASS   (new — this document set)
    PIPELINE STEP 7.0: LEARNING & EXPORT       (enhanced with perf telemetry)

Version line: v1.0 -> v2.0 (Ascension) -> v2.5 (Creative Engine)
           -> v3.0 (Ecosystem) -> v3.5 (Optimization & Caching Engine).

HOW THE FIVE PILLARS INTERLOCK
--------------------------------------------------------------------------------

  Budget Arbiter (01)        decides what is AFFORDABLE, at generation time
        |
        v
  Instance Synthesizer (02)  makes geometry cost ONE-TIME instead of N-TIME
        |
        v
  LOD Grammar (03)           spends detail only where the camera is looking
        |
        v
  Collision Octree (05)      makes physics cost LOCAL instead of GLOBAL
        |
        v
  Enemy Pool (06)            makes spawning cost ZERO instead of SPIKE
        |
        v
  Adaptive Monitor (04)      the runtime safety net when estimates are wrong

Systems 01-03 and 05-07 run at GENERATION time (inside Dream's pipeline).
System 04 and parts of 03/05/06 run at RUNTIME (inside the game loop).
System 08 shows how both halves meet in tick() without violating the
zero-allocation rule.

THE COST MODEL IN ONE SENTENCE
--------------------------------------------------------------------------------

Before Phase 7, Dream's cost scales with AMBIITION (N trees = N costs).
After Phase 7, Dream's cost scales with VISIBILITY (N trees = a handful of
archetypes, paid once, drawn only when seen, collided with only when near,
and spawned only when pre-warmed).
