================================================================================
DREAM PHASE 7 — SYSTEM 2: THE INSTANCE SYNTHESIZER
"One Tree, Fifty Trees" — Brief Item A: Geometry Caching
================================================================================

THE PROBLEM, RESTATED WITH NUMBERS
--------------------------------------------------------------------------------

Dream v3.0 generates 50 trees as 50 L-System runs: 50 geometry generations
(~40ms each = 2 seconds of load), ~1.2M triangles, 50 draw calls, and 50
entries in the collision store. On TIER_C that is the entire triangle
budget spent on vegetation before a single enemy exists.

The fix has two halves: a content-addressed GEOMETRY CACHE (pay for an
archetype once) and cell-batched INSTANCEDMESH rendering (draw it N times
for nearly free). Dream stops emitting raw geometry in its Spatial JSON and
starts emitting INSTANCE NODES.

2.1 — The Geometry Cache (src/perf/geometry-cache.js)
--------------------------------------------------------------------------------

JavaScript

  class GeometryCache {

    constructor(deviceProfile) {
      this.entries = new Map();          // key -> cache entry
      this.memoryBudgetMB = deviceProfile.geometryMemoryBudget;
      this.memoryUsedMB = 0;
      this.lru = [];                     // eviction order, oldest first
    }

    // Content-addressed key: if every input is identical, the geometry
    // would be identical — so we never need to build it twice.
    key(grammarId, species, params, biomeId, penProfileId, lodLevel) {
      return stableHash(
        grammarId, species,
        params.iterations, params.seed, params.curvature,
        params.branchAngle, params.leafDensity,
        biomeId, penProfileId, lodLevel
      );
    }

    acquire(key, buildFn, triangleEstimate) {
      const hit = this.entries.get(key);
      if (hit) { touch(this.lru, key); return hit; }

      const entry = buildFn();           // the ONLY place geometry is born
      this.entries.set(key, entry);
      this.memoryUsedMB += entry.memoryMB;
      return entry;
    }
    // entry = { geometry, material, triangles, boundingRadius,
    //           collisionSet, memoryMB, refCount }
  }

CACHE KEY INSIGHT: the L-System seed is part of the key. Two trees with the
same species but different seeds are different archetypes — the Instance
Synthesizer's job (via the Budget Arbiter, File 01 rank-1 degradation) is
to COLLAPSE the seed space: pick 4-8 seeds per species, dial the rest of
the variety with transforms (Section 2.4).

2.2 — Instance Nodes in the Spatial JSON (Protocol v3.5)
--------------------------------------------------------------------------------

BEFORE (v3.0 — raw geometry, 50 times):

  { "type": "lsystem_tree", "species": "weeping_ink_willow",
    "iterations": 5, "seed": 8231, "position": [12, 0, -40],
    "biome": "alien_jungle" }

AFTER (v3.5 — instance reference):

  {
    "type": "instance",
    "ref": "arch::lsystem_tree/weeping_ink_willow?it=5&seed=8231&biome=alien_jungle",
    "transform": {
      "position": [12, 0, -40],
      "rotY": 1.62,
      "scale": [0.92, 1.28, 0.98],
      "mirrorX": false
    },
    "dials": { "tint": [0.94, 1.02, 0.88], "seed": 4451 },
    "collision": "auto",
    "importance": 1.0
  }

Realization resolves refs against the cache: a HIT registers a transform;
a MISS generates the archetype exactly once, then registers. 50 nodes of
the same ref = 1 generation + 50 matrix writes.

2.3 — Cell-Batched Instancing (src/perf/instance-manager.js)
--------------------------------------------------------------------------------

NAIVE DANGER: one InstancedMesh per archetype covering the whole map has a
single giant bounding sphere — frustum culling dies, and the GPU draws all
50 willows even when the player stares at a wall. The fix is to batch by
SPATIAL CELL, aligned with the Collision Octree's cell grid (File 05) so
culling, collision, and LOD all share one spatial language:

  SPATIAL_CELL_SIZE = 40m  (XZ grid; Y unbounded — trees are tall, not wide)

JavaScript

  class InstanceBatch {
    // One InstancedMesh per (archetypeKey x cell). Capacity has 25%
    // headroom so late Dream edits rarely force a rebuild.
    constructor(geometry, material, capacity) {
      this.mesh = new THREE.InstancedMesh(geometry, material, capacity);
      this.mesh.instanceMatrix.setUsage(THREE.DynamicDrawUsage);
      this.mesh.frustumCulled = true;         // per-cell culling works again
      this.count = 0;
      this._m = new THREE.Matrix4();          // preallocated, reused
      this._q = new THREE.Quaternion();
      this._p = new THREE.Vector3();
      this._s = new THREE.Vector3();
    }

    add(instanceNode) {   // zero allocation: composes into the typed array
      compose(this._m, this._p, this._q, this._s, instanceNode.transform);
      this.mesh.setMatrixAt(this.count, this._m);
      this.mesh.setColorAt(this.count, this._tint.setRGB(...node.dials.tint));
      this.seeds[this.count] = node.dials.seed;
      this.count++;
      this.mesh.count = this.count;
    }
  }

DRAW CALL MATH (the cathedral willow forest, TIER_C):
  v3.0:  80 unique trees  = 80 draw calls (budget: 60)  FAIL
  v3.5:  6 archetypes x ~4 visible cells = ~14 draw calls (budget: 60) PASS
  Triangles: 960k -> 190k. Generation time: 3.2s -> 240ms.

2.4 — The Five Dials of Variety (making 6 archetypes look like 80)
--------------------------------------------------------------------------------

Identical trees in a row would murder the hand-drawn illusion. Every
instance is varied along five dials, ALL of which are matrix or attribute
writes — none cost geometry:

  DIAL 1  rotY        full 0..2pi. Mandatory jitter near sightlines.
  DIAL 2  scale       non-uniform +-30% (X/Z) and +0..+35% (Y stretch).
                      A squat wide willow and a tall thin one read as
                      different SPECIES to the eye.
  DIAL 3  tint        instanceColor, HSL jitter +-5% + biome gradient
                      sampling (a tree at the jungle/cathedral border
                      inherits the blend — File 05.5 of Phase 5.5 feeds
                      this directly).
  DIAL 4  seed        per-instance float driving shader variation (2.5):
                      hatch phase, sway phase, bioluminescent flicker
                      period. Two identical trees at identical transforms
                      still hatch and sway differently.
  DIAL 5  mirrorX     horizontal mirror (winding-safe: pen materials are
                      DoubleSide by design).

6 archetypes x 5 dials = a perceptual space in the millions. The renderer
cannot tell the difference; neither can the player.

2.5 — Per-Instance Shader Variation (pen-sway + hatch phase)
--------------------------------------------------------------------------------

Injected into the shared pen material via onBeforeCompile — the aesthetic
stays in ONE material, honoring the single-pass composite rule:

GLSL (vertex stage additions)

  attribute float aSeed;              // per-instance, 0..1
  uniform float uTime;
  uniform float uSwayAmp;             // per-archetype: willow 0.06, stone 0
  uniform float uHeight;              // archetype height, object space

  // --- PEN-SWAY: living doodles, and the Fifth Dial made visible ---
  float phase  = aSeed * 6.28318;
  float hFac   = smoothstep(0.0, 1.0, position.y / uHeight);
  transformed += vec3(
      sin(uTime * 1.3 + phase)        * uSwayAmp * hFac,
      0.0,
      cos(uTime * 0.9 + phase * 1.7)  * uSwayAmp * 0.7 * hFac );

  // --- HATCH PHASE: cross-hatching rotates slightly per instance ---
  vHatchPhase = aSeed * 0.35;         // consumed by the fragment stage

uTime advances from the game clock; aSeed is an InstancedBufferAttribute
filled once at batch build. Cost: ~10 vertex-shader ALU ops. On TIER_C the
sway uniform is set to 0 (a ladder-adjacent toggle, decided at boot, never
mid-match — motion is cheaper to keep than shadows, so sway survives to
the very last).

2.6 — Destructibles: The Scale-To-Zero Trick
--------------------------------------------------------------------------------

Phase 5.5 introduced destructible soft cover (jungle foliage). Destructible
instances CANNOT share a batch with static ones naively. Solution: each
destructible CLUSTER gets its own small InstancedMesh; "destroyed" is a
matrix write scaling the instance to 0 (plus an ink-splat particle burst):
one draw call per cluster, zero removal cost, zero reallocation.

2.7 — The Perceptual Variety Guard (audit-healer extension)
--------------------------------------------------------------------------------

Reuse must be INVISIBLE. The audit-healer (v1 lineage) gains three checks
on the instance manifest:

  CHECK 1 — TWIN SEPARATION: two instances of the same archetypeKey with
  near-identical dials must be >= (0.8 x combined bounding radius) apart.
  Violations are auto-cured by re-rolling dials (never by moving geometry
  — flow is sacred).

  CHECK 2 — SIGHTLINE JITTER: any instance pair of the same archetype
  visible within 10 degrees of each other from any spawn or lane anchor
  must differ in rotY by >= 25 degrees and in Y-scale by >= 12%.

  CHECK 3 — VARIETY SCORE: uniqueDialTuples / instanceCount >= 0.7 per
  archetype per cell. Below that, the region reads as an orchard; the
  Art Director persona is asked for 1-2 additional archetype seeds
  (cheaper than it sounds: cache still warm).

2.8 — Why Instancing Does NOT Break the Ballpoint Look
--------------------------------------------------------------------------------

The pen aesthetic (outlines, hatching, halftone) lives in the FRAGMENT
stage of the shared material and in the single composite pass — not in
geometry. Instancing only batches transforms; the fragment shader sees the
same world-space normals, view vectors, and depth it always did. Two
caveats, both solved:

  CAVEAT 1: screen-space outline passes that depth-peel per object need
  instance-aware depth. The v3.0 renderer already does outlines in the
  composite pass — compliant by construction.

  CAVEAT 2: per-instance tint shifts the paper-white balance. Tint is
  clamped to +-5% lightness and validated against the biome palette.

2.9 — Cache Lifecycle & the Dream 3x Loops
--------------------------------------------------------------------------------

  - Eviction: LRU, only between matches (never mid-match — a geometry
  pop-in during wave 9 is worse than 60MB held).
  - Dream's multiplier loops ("3x") become nearly free after iteration 1:
  iterations 2 and 3 hit the warm cache for every unchanged archetype.
  The genetic mutations (Phase 2.5, v2.0) that only nudge placement now
  cost milliseconds, not seconds.
  - The cache manifest is exported alongside the map (File 07) so the
  runtime loading screen can stream archetype builds in dependency order
  (hero pieces first — the player sees the cathedral rising while the
  shrubs finish).

INTEGRATION HOOKS
--------------------------------------------------------------------------------
  - Budget Arbiter (01): rank-1 degradation strategy is executed HERE
    (unique->instance demotion happens at Spatial JSON emission).
  - LOD Grammar (03): the cache key includes lodLevel; all three LODs of
    an archetype share one cache entry (Section 3.2).
  - Collision Octree (05): instance collision sets are cached per
    archetype too — 50 trees contribute ~6 capsule sets.
  - Runtime (08): batch building happens entirely at load; tick() never
    touches instanceMatrix (static world) except destructibles (2.6).
