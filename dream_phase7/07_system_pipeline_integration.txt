7.1 — The Step 6.5 Detail
--------------------------------------------------------------------------------

  6.5.1 INSTANCE RESOLUTION — walks the Spatial JSON; applies the Budget
  Arbiter's rank-1 strategy (File 01, 1.5) where the ledger demands it:
  unique geometry nodes are demoted to instance refs against the cache.
  The Demotion Negotiation from the Debate (Art Director's hero pieces,
  importance >= 1.5) is EXEMPT — heroes stay unique, that was the deal.

  6.5.2 LOD BAKING — every archetype's grammar runs 3 times (LOD0/1/2)
  into the shared cache entry (File 03). Thresholds computed from
  boundingRadius + importance + viewport assumptions, then per-tier
  threshold tables are emitted (TIER_C gets earlier swaps via the
  detail-bias column of its manifest).

  6.5.3 COLLISION CHUNKING — octree build kicked off ASYNCHRONOUSLY
  (worker) while 6.5.4-6.5.6 proceed; parity validation (File 05, 5.7)
  runs on the worker while it holds the raw data. Build report (depth,
  looseness, retries) exports with the map.

  6.5.4 POOL PLANNING — the Pool Manifest (File 06, 6.2) per tier:
  pool sizes, concurrency caps, pre-dress kits, impostor snapshot list.

  6.5.5 BUDGET AUDIT — THE DEGRADATION LOOP:
        estimate frame cost per tier (File 01, 1.4)
          -> pass? continue
          -> fail? apply next-ranked degradation strategy (1.5)
                   -> re-estimate -> repeat
          -> exhausted? the Debate reconvenes (rank 7 needs three
             signatures — content reduction is a creative decision)
        Every tier must independently pass the 0.84 x interval contract.

  6.5.6 PERF SIMULATION — headless 10-second flythrough per tier: the
  camera flies the lane anchors, wave 5 spawns mid-flight, the cost
  model predicts p95 frame time at each second. This is ANALYTIC (the
  model, not a GPU) — the simulation's job is to catch pathological
  compositions (a CLIMAX wave + a hero reveal + 3 biome blends on one
  screen) BEFORE export, not to replace live telemetry.

  6.5.7 EXPORT — one map, FOUR device profiles:
        map.json                 Spatial JSON v3.5 (instance nodes)
        manifests/tier-S.json    instance manifest, LOD thresholds,
        manifests/tier-A.json    pool manifest, collision octree params,
        manifests/tier-B.json    quality config, cache order (heroes
        manifests/tier-C.json    first — File 02, 2.9)
    The runtime picks its manifest at boot (File 10, Flow 1 step 6).
    ONE design, four price tags — the map is not re-generated per
    device, only PRICED per device.

  A map that passes the gauntlet has EARNED its export. The gauntlet
  report is itself an export artifact — the Dream learning cache stores
  which checks fired, because check patterns are diagnostic signatures
  (see 7.3).

7.3 — Learning & Export Enhancements (Phase 7.0 of the pipeline)
--------------------------------------------------------------------------------

The loop that makes Dream's estimates honest over time:

  AT MATCH END (runtime -> .agents/learning-cache.json):
    matchPerfReport (File 04, 4.8) + graphics settings the player
    actually used (File 09, C.4) + which tier manifest was loaded.

  MAP DNA GAINS PERF FEATURES:
    instanceDensity, uniqueArchetypeCount, avgLod0Triangles,
    octreeDepth, poolHighWater, gauntletChecksFired[]
    Map similarity search (v2.0 KNN) can now answer "has a map LIKE
    this melted a device LIKE that before?"

  POST-MORTEM RECONCILIATION (the core mechanic):
    for each tier:  predicted p95  vs  measured p95
      error < 10%   -> k-constants nudged (rolling weighted average,
                       clamped to +-20% per update — no wild swings)
      error > 25%   -> tier profile flagged; the DEVICE's stored
                       profile is demoted/adjusted for next boot
                       (File 10, Flow 1 step 3 — the silent correction)
      survival-mode visits -> map archetype's tier variant is rebuilt
                       LIGHTER next generation, automatically

  GAUNTLET SIGNATURES: maps that repeatedly fire check #5 (collision
  parity) share a geometry-language ancestry — the audit-healer's rule
  set for that language tightens (dynamic rule tightening, v1 lineage,
  now in a new dimension).

  SETTINGS AS TELEMETRY (File 09, C.4): "TIER_C players disable
  Halftone Paper 31% of the time" -> next release cycle, the boot
  default flips. The player base tunes the product, one match at a
  time.

  THE SELF-SHARPENING CONTRACT: every match played anywhere makes
  every future map's budget estimate slightly more honest. Dream v2.0
  promised "an autonomous spatial intelligence." v3.5's addition is
  subtler and colder: an intelligence that knows what things COST.
