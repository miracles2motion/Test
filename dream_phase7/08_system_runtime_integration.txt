8.1 — The Load Sequence (src/boot.js — the loading screen is a kitchen)
--------------------------------------------------------------------------------

Every expensive thing in Phase 7 happens HERE, ordered so slow steps
overlap and the player watches the world assemble:

  T+0.0s  Loading screen (paper + pen nib spinner)
  T+0.1s  [FILE 10] DEVICE PROBE LAYER 1 — static signals -> provisional
          tier (instant)
  T+0.4s  [FILE 10] LAYER 2 — SMOKE BENCHMARK (<300ms, 3 frames):
          calibrates k-constants, doubles as first shader warm-up
  T+0.7s  [FILE 10] LAYER 3 — history override from learning cache
  T+0.8s  DEVICE PROFILE FROZEN. Tier manifest selected (File 07, 6.5.7)
  T+1.0s  [FILE 09] SETTINGS RESOLVE — first boot: AUTO / returning:
          localStorage restore
  T+1.2s  Parse Spatial JSON v3.5 + tier manifest
  T+1.4s  [FILE 02] GEOMETRY CACHE FILL — unique archetypes only, hero
          pieces first (the cathedral rises while the shrubs finish);
          instance transforms registered per 40m cell
  T+2.2s  [FILE 03] LOD BAKE — all three levels per archetype (grammar
          runs x3) + renderer.compile() for EVERY (material x LOD x
          lighting-variant) — the pre-compilation that makes every
          later swap and ladder toggle free
  T+2.5s  [FILE 05] COLLISION BAKE -> OCTREE WORKER KICKOFF (async;
          build + parity validation run on the worker while we continue)
  T+3.0s  [FILE 06] POOL PRE-WARM — shells instantiated, dressed once
          per archetype, stat kits copied, freelist built
  T+3.5s  [FILE 03] IMPOSTOR SNAPSHOTS — each archetype's LOD2 atlas,
          8 yaw angles x 128px, rendered from the pre-dressed shells
  T+4.0s  [FILE 05] OCTREE COMPLETE + PARITY GREEN (250 samples);
          broadphase borrowed-list pools allocated
  T+4.2s  PRE-RENDER — one full frame at spawn through the entire
          pipeline (geometry, instancing, composite) so the first REAL
          frame is never the first compiled frame
  T+4.5s  READY. The 60 FPS contract is signed. Monitor begins sampling
          on the first real frame (loading frames are excluded — they
          lie; File 04, hooks).

  (Numbers are illustrative for a mid-density map on TIER_A; the ORDER
  is the contract. Every step streams progress into the loading bar —
  the player watches the pen world assemble, which is on-brand.)

8.2 — The tick() Loop (every system's runtime half, in order)
--------------------------------------------------------------------------------

JavaScript

  // The frame pacer owns the rAF callback (File 04, 4.9):
  // at cap 60 it renders every display refresh; at cap 30 on a 60Hz
  // display it renders every OTHER one, running owed sim ticks first.
  function onFrame(now) {
    const dt = clamp(now - lastNow, 0, 250);        // tab-stall clamp
    lastNow = now;

    pacer.advance(dt);                              // accumulator
    let ticks = pacer.owedTicks();                  // 0, 1, or 2 (max 5)
    while (ticks-- > 0) {
      simulate(FIXED_DT);                           // fixed 60Hz, always
    }

    // ---- SIMULATION (fixed timestep, cap-invariant) ----
    //   1. Player input & movement        broadphase CACHED list (05)
    //   2. AI scheduler                   distance bands (06, 6.6);
    //                                     grid queries only (05, 5.6)
    //   3. GroupTacticsController         God Mode formations, O(local)
    //   4. Spawner                        pool awakens, stagger slots
    //   5. Projectiles & combat           dynamic grid + static lists
    //   6. Gameplay events                parry windows, wave state
    //
    // ---- RENDER (per display frame) ----
    //   7. LODManager.flush(MAX 3 swaps)  amortized, visible-flips (03)
    //   8. Animation                      interpolated at render rate
    //   9. Camera
    //  10. Render                         cell-culled instance batches
    //                                     (02), LOD children visible
    //  11. Composite pass                 SINGLE pass, pen treatment,
    //                                     compensated uniforms (04, 4.5)
    //  12. PerfMonitor.sample(dt)         ring buffer write (04, 4.1)
    //  13. PerfMonitor.decide()           once per second, may schedule
    //                                     a rung change (deferred if
    //                                     in combat — 04, 4.6)

    render();
  }

  NOTE THE ORDERING RULES:
  - Collision queries refresh only on movement thresholds (05, 5.5) —
    step 1 is usually a cache read, not a tree walk.
  - LOD swaps happen AFTER simulation, BEFORE animation — a swap can
    never interleave with an AI decision mid-tick.
  - The monitor samples LAST, so its measurement includes everything
    above it — it judges the true cost of the frame it just watched.

8.3 — Zero-Allocation Compliance Audit (the house rule, per system)
--------------------------------------------------------------------------------

  SYSTEM                    ALLOCATION POLICY INSIDE tick()
  ------------------------  -------------------------------------------
  Perf Monitor (04)         one Float32Array ring + one preallocated
                            sort copy; no objects, no closures
  Frame Pacer (04, 4.9)     two scalars; rAF callback is created once
  LOD Manager (03)          preallocated swap queue; swaps are
                            mesh.visible booleans on pre-attached
                            children
  Broadphase (05)           borrowed, pooled query lists, rotated per
                            frame; re-query overwrites in place
  Dynamic grid (05)         pooled Int32Array cell lists, ring-swapped
  Enemy Pool (06)           shells preallocated; awaken/reset mutate
                            existing objects only; emitters pooled
  AI scheduler (06)         per-enemy scratch vectors preallocated on
                            the shell; scheduler itself is an array
  Instancing (02)           STATIC after load; destructibles mutate the
                            existing instanceMatrix array in place
  Composite pass            preexisting single pass; uniforms only
  Toasts / settings UI      DOM layer — outside the simulation loop
                            entirely (DOM churn never touches sim GC)

  LINT RULE (build-enforced): a PR that adds `new`, an object literal,
  or a closure inside the tick path fails CI. The rule existed before
  Phase 7; Phase 7's contribution is that it is now AUDITABLE because
  every system above declares its policy in one table.

CLOSING NOTE
--------------------------------------------------------------------------------

Before Phase 7, Dream was a world ecologist with no concept of money —
it could design a cathedral forest and never ask what the forest cost.

Phase 7 gives Dream an economist's cold eye and a mechanic's hands: every
triangle is spent only where the player can see it, every collision
fought only against what is near, every enemy born before it is needed,
and every device told the truth about what it can afford. The creativity
of Phases 5.5 and 6 is not restrained by this — it is FINANCED by it.
The 80-willow fog forest exists precisely because 6 of them are real.

  Dream v3.5 is complete.
