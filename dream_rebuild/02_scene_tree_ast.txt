2.0 — WHY AN AST (what the audit proves)
--------------------------------------------------------------------------------

Today, information flows through the WORST possible containers:

  Concept (.md)  --regex-->  4 numbers  -->  scaffold prints code strings
  Code (.js)     --regex-->  "inspector" parseFloats its own output
  Templates      --strings->  injected between comment markers (dupes: bug #5)

Every stage writes CODE, and every later stage scrapes code with regexes.
That is why `${y} + 4.5` breaks the inspector (audit bug #3), why running
twice duplicates injection blocks (bug #5), and why concepts are
decorative (RC4) — there is no representation in which a concept's
wishes, the geometry, and the validation can even MEET.

The Scene Tree is that representation. One typed JSON tree is the single
source of truth: the Layout Engine writes it, the Vignette Composer
dresses it, the Validation Engine scores it, the (optional) LLM edits
it, and exactly ONE module — the Compiler — ever writes geometry code.

DESIGN PRINCIPLES
  P1  Semantic first: a node says "room with a south doorway", not
      "box at (x,y,z)". Geometry is DERIVED, never authored.
  P2  The compiler is the only code writer; the tree is the only
      hand-off format. (Kills the marker/duplication bug class.)
  P3  Deterministic: stable node ordering -> same tree, same bytes.
  P4  Every node carries cost metadata (geometry calls, colliders) —
      the counting substrate Phase 7's Budget Arbiter always lacked.
  P5  Inspectable: validation reads TYPED NODES, not regex-scraped JS.

2.2 — NODE TYPE CATALOG (v1.0 — maps 1:1 onto the audited primitive API)

  SHELL          EMITS (via primitives, audit section 12)

  tierFloor      slab() at zone tier height

  SPATIAL
  -------------  ---------------------------------------------------------

2.4 — THE COMPILER (src/rebuild/scene-compiler.js)
--------------------------------------------------------------------------------

  WALK: stable order (type rank, then id) -> deterministic output bytes.
  EMIT: one emitter function per node type; emitters translate semantic
        params into primitive calls, INCLUDING the derived geometry:
          - room walls: perimeter segmented by doorway/window spans;
            each segment -> box(thickness 0.4); header/sill boxes over
            openings (windows: sill 1.1m, header to wallHeight)
          - stairRun: steps = ceil(delta / 0.30); direction from the
            from/to transform delta; emits stairs(...) + asserts
            reservedRun >= steps * 0.55 (hard fail at compile time)
          - railing: rail() per declared edge run
  IMPORTS: prefab calls collected during the walk -> ONE deduped import
        block (kills audit bug #8 forever).
  FILE OWNERSHIP (kills bug #5): the generated level file has exactly
        two regions —
          // === HAND REGION (never touched by Dream) ===
          // === DREAM REGION (regenerated WHOLESALE from the tree) ===
        The compiler rewrites ONLY the Dream region, atomically, from
        the tree. There is no second injector, so there is no duplicate.
        Human geometry belongs in the hand region or in prefabs (the
        existing prefab-observer already harvests it).
  AUDIT TRAIL: every emitted block carries its node id in a trailing
        comment — `box(...); // z_hab_room/wall:n`. Debugging a
        generated map becomes grepping an id, not archaeology.

2.5 — VALIDATION LAYERS (before any code exists)
--------------------------------------------------------------------------------

  L1  SCHEMA: node types known, required params present, ids unique,
      children resolvable. (Zod-style validators; fail fast, journal.)
  L2  SPATIAL: AABB overlap pass over resolved transforms (UDS rules:
      corridors >= 1.8m clear, door pinch margins from learning-cache);
      every vertical edge has a stairRun or grappleRing reservation.
  L3  SANDBOX: the EXISTING geometry-validator.js dry-run on compiled
      output (NaN/Infinity detection) — the audit shows this works;
      it becomes the final gate instead of the only gate.

2.6 — THE INSPECTOR REBORN (map-inspector.js retirement of regex)
--------------------------------------------------------------------------------

  Checks move UPSTREAM to where they are cheap and typed:
    step rise:      validated when the stairRun node is authored (L2)
    deck penetration: stair headroom asserted against File 03's grid
    embedded rings:  ring anchor cells checked against actual overhead
                     geometry from the grid — not a hardcoded 18.5-20m
                     classroom lamp range (audit limitation, dead)
  What survives of the old inspector becomes a THIN post-compile smoke
  test (counts + sanity), because the tree already guaranteed the rest.

2.7 — ROUND-TRIP: LEARNING FROM THE CLASSROOM (audit "cannot do" #9)
--------------------------------------------------------------------------------

  A one-way EXTRACTOR (stretch goal, File 07 phase 6) parses
  src/level.js's hand-authored Giant Classroom into a reference tree
  (classroom.tree.json). Even a partial extraction pays twice:
    - the Validation Engine calibrates its scoring against a known-good
      tree (real distributions, not invented thresholds);
    - the Vignette Composer mines it for vignette patterns (desk rows,
      shelf walls) expressible with the existing 29 prefabs.
  The gold standard stops being a comparator and becomes a TEACHER.

2.8 — COST METADATA (the Phase 7 on-ramp)
--------------------------------------------------------------------------------

  Every emitter returns its primitive-call count + collider count; costs
  roll up to the root. The tree can then answer "how many colliders will
  this map compile to?" BEFORE compiling — which is the exact substrate
  the Budget Arbiter needed (audit's spatial intelligence gap). No
  budgets are ENFORCED in the rebuild (that's Phase 7's job later); the
  tree merely makes counting trivial and honest.

2.9 — ACCEPTANCE TESTS
--------------------------------------------------------------------------------

  T1  SCHEMA: 1,000 seeded trees pass L1; malformed node fixtures fail
      with actionable errors.
  T2  DETERMINISM: same tree -> identical compiled bytes (hash).
  T3  NO-DUPES: compile 5x in place; Dream region byte-identical,
      hand region untouched, imports deduped.
  T4  TRACEABILITY: every emitted geometry line carries a node id;
      random sample of 100 lines resolve to live nodes.
  T5  COST HONESTY: predicted cost vs post-compile audit counts within
      +-2% on 100 seeded maps.

INTEGRATION HOOKS
--------------------------------------------------------------------------------
  <- File 01: Stage 5 emits the tree (layout engine never writes code).
  -> File 03: the grid rasterizes FROM the tree's structural nodes.
  -> File 04: vignetteRefs expand during the walk.
  -> File 05: validation scores the tree; repair passes edit NODES and
     recompile — never patch generated code (RC7's fix, mechanically).
  -> File 06: the LLM planner reads/writes trees (Vector E's contract).
  -> Existing: geometry-validator (final gate), learning-cache (node-id
     keyed outcomes), dream-journal (tree hash per run).
