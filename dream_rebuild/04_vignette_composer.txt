4.0 — THE PROBLEM IN ONE SENTENCE
--------------------------------------------------------------------------------

The audit shows map-injector.js places props by rolling dice on a 16m
grid: five identical solar arrays in a row is a possible (and typical)
outcome; zen/cyber/steampunk each have exactly ONE prop type; and
nothing ever composes a SCENE — a place that reads as "someone works
here" rather than "a mesh was dropped here".

The Vignette Composer replaces prop-dropping with SCENE GRAMMAR:
small, named micro-sets (checkpoints, camps, shrines, barricades) whose
slots are filled from the existing 29-prefab vocabulary, anchored to
the Surface Grid (File 03), and diversified by hard rules. This is the
ComponentGrammar the Phase 5.5 document promised — finally grounded in
prefabs that actually exist.

4.1 — WHAT A VIGNETTE IS (the schema)
--------------------------------------------------------------------------------

JavaScript

  const VIGNETTE_LIBRARY = {

    checkpoint: {
      themes: ['space_station', 'cyber', 'steampunk', 'colossal'],
      size: [4, 3],                 // footprint in grid cells (2m cells)
      tierAny: true,                // placeable on any tier with room
      slots: [
        { role: 'barrier',  anchor: 'laneEdge',
          fills: ['buildAirlockHatch', 'buildCryoPod', 'barrel'] },
        { role: 'monitor',  anchor: 'wallAdjacent',
          fills: ['buildTelemetryConsole', 'buildSurveyTable'] },
        { role: 'guardpost', anchor: 'corner',
          fills: ['buildCryoPod', 'buildOxygenTankRack'] },
      ],
      cover: { hard: 1, soft: 1 },  // contributes to File 05's rhythm
      narrative: 'a watched threshold',
    },

    campfire_camp: {
      themes: ['forest', 'maritime'],
      size: [5, 4], tierAny: false,     // ground stories only
      slots: [
        { role: 'hearth',  anchor: 'center',   fills: ['buildCampfire'] },
        { role: 'seating', anchor: 'ring',     fills: ['buildHollowLog',
                                                      'buildChoppingBlock'] },
        { role: 'store',   anchor: 'edge',     fills: ['buildWoodStack',
                                                      'buildLoggingCart'] },
      ],
      cover: { soft: 2 },
      narrative: 'a resting patrol',
    },
    // ... shrine, workstation_row, crash_debris, sensor_station,
    //     market_stall, reading_nook (Classroom-mined, 2.7), etc.
  };

  COMBINATORICS: a 3-slot vignette over ~6 eligible prefabs per slot
  yields dozens of distinct fills PER TYPE; ~14 types x themes x tier
  placements x seeded orientation = the variety the template library
  (21 fixed strings) could never reach — from the SAME 29 prefabs.

4.2 — SLOT ANCHOR RULES (why scenes read as places)
--------------------------------------------------------------------------------

  ANCHOR          RULE (evaluated against File 03's grid)
  --------------  -----------------------------------------------------
  wallAdjacent    cells whose zone wall is within 1 cell — furniture
                  hugs architecture (the audit's "props ignore walls")
  corner          2 adjacent boundary faces — guard posts, shrines
  laneEdge        cells 1-2 off a declared lane polyline — cover that
                  MATTERS (File 05 consumes it)
  center          geometric middle — hearths, command tables
  ring            cells at radius r around center — seating, orbitals
  edgeSightline   tier > 0 edge cells with verified open lines —
                  high-ground watchposts (File 03's 3.3)

  Orientation: each fill gets a seeded rotation; wallAdjacent fills
  FACE the wall's inward normal. Furniture that faces nowhere is the
  tell of a generated map — the Composer refuses to emit it.

4.3 — THE PLACEMENT FLOW (deterministic, seeded)
--------------------------------------------------------------------------------

  1. DEMANDS: zone.wants (File 01) + strategy priors request vignette
     TYPES per zone; File 05's Repair Agenda may add demands mid-loop
     ("lane N needs 1 more hard cover at these cells").
  2. CANDIDATES: grid.freeAnchors(zone, tier, size, headroom >= 2.5)
     -> candidate cell clusters, zone-tag filtered.
  3. FIT: anchor-rule matching per slot; orientation solve; collision
     pre-check against grid occupancy (vignettes RESERVE their cells so
     later passes and other vignettes cannot overlap — the refiner's
     scatter-on-top-of-scatter bug class dies).
  4. FILL: seeded prefab selection per slot, biased by learning-cache
     success stats per (vignette, theme, tier).
  5. EMIT: vignetteRef node into the tree (File 02 expands it during
     compilation — the Composer never writes code).

4.4 — THE DIVERSITY GUARD (five solar arrays = bug, now)
--------------------------------------------------------------------------------

  D1  TYPE SEPARATION: same vignette TYPE requires >= 18m between
      placements (tunable per type; hearths rarer than cover).
  D2  FILL HASH: the multiset of prefab fills is hashed; identical
      hashes require >= 30m separation. Two checkpoints may coexist —
      two IDENTICAL ones may not sit together.
  D3  QUOTA: per zone, per type, a max count (density dial from the
      concept's coverDensity; zen gardens do not become checkpoints).
  D4  VARIETY SCORE: unique-fill-hash ratio >= 0.75 per map (mirrors
      the audit-facing metric in the Phase 7 set — same discipline,
      different layer).
  D5  ADJACENCY SEMANTICS: narrative-compatible neighbors only
      (campfire near woodstack: yes; cryo pod next to campfire: no).
      A tiny compatibility matrix per theme; violations are re-rolled.

4.5 — COVER AS A FIRST-CLASS PRODUCT
--------------------------------------------------------------------------------

  Hard/soft cover stops being a side effect of random props and becomes
  a declared product of two sources:
    - vignette.cover fields (a checkpoint IS a cover opportunity)
    - the LANE RHYTHM PASS: File 05 measures actual cover intervals
      along every lane; gaps > 15m generate a prescription ->
      "addCoverVignette at cell (x,z)" — rhythm-placer.js finally
      places cover where MEASUREMENT says it's missing, not at fixed
      beats. The 10-15m tactical interval from the audit's Vector D
      becomes an enforced property, not a hope.

4.7 — MACRO STRUCTURES RE-SCOPED (the 21 templates find a home)
--------------------------------------------------------------------------------

  macro-dreamer's templates (bell pavilion, cargo crane, galleon
  sterncastle...) stop being void-fillers and become HERO ANCHORS:
  the largest slot-fill in a "landmark" vignette type whose anchor
  requirements are zone-level (open area, sky exposure, tier 0) and
  whose connection is a mandatory Stair Router demand (File 03's
  disconnected-building rule). Templates were never the problem;
  dropping them into random voids was.

4.8 — ACCEPTANCE TESTS
--------------------------------------------------------------------------------

  T1  DIVERSITY: D1-D5 hold across 100 seeded maps; variety score
      >= 0.75; zero identical-fill neighbors within radius.
  T2  NO OVERLAP: vignette reserved cells never intersect (grid-
      verified pre-emit; the sandbox validator becomes belt-and-
      suspenders, not the only defense).
  T3  DENSITY: per-zone prop density within concept dial +-10%;
      Classroom-corpus calibration once the extractor exists.
  T4  READABILITY (heuristic): wall-adjacency ratio >= 0.6 for
      furniture slots (nothing floating mid-room facing nowhere).
  T5  THEME COVERAGE: every theme renders >= 3 distinct vignette
      types with >= 2 distinct fill hashes each.

INTEGRATION HOOKS
--------------------------------------------------------------------------------
  <- File 01: zone.wants + strategy priors generate demands.
  <- File 03: freeAnchors() is the Composer's only spatial interface;
     reservation writeback keeps the grid authoritative.
  <- File 05: repair prescriptions add demands; measured cover
     intervals drive the lane rhythm pass.
  -> File 02: vignetteRef nodes expand at compile time (imports
     deduped by the compiler).
  -> Existing: prefabs.js (the vocabulary), learning-cache (fill
     success stats per theme/tier), rhythm-placer (demoted to the
     measured-gap executor), macro templates (hero anchors).
