FINDING 2 — Rope bridges: the floor is invisible, the planks are a lie
---------------------------------------------------------------------
WHERE: prefabs_code.js, buildSuspendedRopeBridge()
WHAT: You place ONE flat collider hull at the bridge midpoint:
    collider(midX, y - maxSag*0.4, midZ, ...)   // top surface ~ y + 0.03
But the visual planks follow a sine sag:
    py = y - sin(t*PI) * maxSag                  // midspan: y - 0.42
So at midspan the plank TOP is at y - 0.31 while the player's feet
ride the collider at y + 0.03 — the player floats ~0.35m ABOVE the
visible planks exactly at the deepest sag point, and planks visually
"tunnel" underfoot. On a 21m bridge this is impossible not to notice.
SEVERITY: [CRITICAL] (visible every crossing, on all 4 skybridges)
FIX (either):
  a) Segmented colliders that follow the same sine:
       const segCount = Math.max(4, Math.round(len / 3));
       for (let s = 0; s < segCount; s++) {
         const tA = s / segCount, tB = (s + 1) / segCount;
         const tm = (tA + tB) / 2;
         const ym = y - Math.sin(tm * Math.PI) * maxSag;
         const sx = x1 + dx * tm, sz = z1 + dz * tm;
         const segLen = (len / segCount) + 0.15; // small overlap, no gaps
         collider(sx, ym - 0.1, sz,
           Math.abs(dirX) > 0.5 ? segLen : width, 0.3,
           Math.abs(dirX) > 0.5 ? width : segLen);
       }
     (delete the single flat hull)
  b) Or keep the flat hull and reduce maxSag to <= 0.12 so the
     mismatch is under ~10cm. Option (a) is better — keep the drama.

FINDING 3 — buildTerracedRidge ignores its own `dir` option
---------------------------------------------------------------------
WHERE: prefabs_code.js, buildTerracedRidge()
WHAT: The function only ever does `currZ += tierRun` — it builds in
the +z direction no matter what. You call it 4 times with
dir '-z', '+z', '-x', '+x'. Result:
  - North ridge (z=-33, '+z' by luck): works — climbs toward center.
  - South ridge (z=+33): climbs AWAY from center toward the wall.
  - West/East ridges (x=±31): climb NORTHWARD (sideways!), not
    toward the center.
So 3 of 4 ground-to-deck ascents do not connect anything.
SEVERITY: [CRITICAL] (level flow is broken on 3 of 4 flanks)
FIX — resolve a direction unit vector from `dir`:
    const dirs = {
      '+z': [0, 1], '-z': [0, -1], '+x': [1, 0], '-x': [-1, 0]
    };
    const [ddx, ddz] = dirs[o.dir ?? '+z'];
    let currX = x, currZ = z;
    for (let t = 0; t < steps; t++) {
      currY += tierRise;
      currX += ddx * tierRun;
      currZ += ddz * tierRun;
      // slab from (currX, currZ) back one run along the direction:
      slab(
        Math.min(currX - ddx * tierRun, currX + (ddz !== 0 ? width/2 : 0)),
        ... // simplest robust form:
      );
    }
Cleaner concrete version — center each shelf at the advanced point
and size it across the walk axis:
    for (let t = 0; t < steps; t++) {
      currY += tierRise;
      currX += ddx * tierRun;
      currZ += ddz * tierRun;
      const cx0 = currX - ddx * tierRun * 0.5;
      const cz0 = currZ - ddz * tierRun * 0.5;
      const x1 = cx0 - (ddx !== 0 ? tierRun * 0.5 : width / 2);
      const x2 = cx0 + (ddx !== 0 ? tierRun * 0.5 : width / 2);
      const z1 = cz0 - (ddz !== 0 ? tierRun * 0.5 : width / 2);
      const z2 = cz0 + (ddz !== 0 ? tierRun * 0.5 : width / 2);
      slab(x1, z1, x2, z2, currY, 0.4, { ink: inkGrass });
      // rocks + wedge as before, but offset along (ddx, ddz)
    }
Also swap the wedge `dir` to match the ridge direction.

      const angle = -Math.PI * 0.4 + (s / stepCount) * sweep;
      const stepY = y + (s + 1) * 0.28;

FINDING 9 — Math.random() determinism leak
---------------------------------------------------------------------
WHERE: prefabs_code.js, buildGiantGrass():
    const height = o.height ?? (5.5 + Math.random() * 2.5);
Everything else in the library carefully uses createRNG(seed). This
one call breaks reproducibility the moment anyone omits height —
and Dream REQUIRES byte-identical rebuilds from a seed (File 07).
SEVERITY: [MEDIUM today, CRITICAL for Dream]
FIX:
    const rng = createRNG(o.seed ?? 9001); const next = rng.next;
    const height = o.height ?? (5.5 + next() * 2.5);
Audit the whole library for Math.random with:
    grep -n "Math.random" src/prefabs.js src/anatomy-grammar.js src/levels/*.js
Target: zero matches outside prng.js.

FINDING 11 — annularDeck uses axis-aligned rectangles for arc slices
---------------------------------------------------------------------
WHERE: spline_engine.js, annularDeck()
WHAT: Each of the 16 deck slices is placed as an axis-aligned
rectangle sized from chord/depth — the rectangle corners poke past
the true arc, so the deck rim is subtly notched/wavy instead of a
clean circle, and adjacent slices overlap each other (same ink, so
you mostly see the notches at the outer rail line).
SEVERITY: [MEDIUM] (hero centerpiece — worth the upgrade)
FIX: emit one radial-trapezoid geometry per slice via B.addGeo:
    const g = new THREE.BufferGeometry();
    const v = [];
    const push = (r, a) => v.push(
      cx + Math.cos(a) * r, y, cz + Math.sin(a) * r);
    push(rInner, a1); push(rOuter, a1); push(rOuter, a2);
    push(rInner, a1); push(rOuter, a2); push(rInner, a2);
    g.setAttribute('position', new THREE.Float32BufferAttribute(v, 3));
    g.computeVertexNormals();
    addGeo(g, ink);
    // keep ONE box collider under the slice center (already fine)
This gives a perfectly circular rim and makes the hatch edge crisp.
