THE HEADLINE DISCOVERY — YOUR SHADER HAS A FREE WIND ENGINE
-----------------------------------------------------------
Look at inkVert in render_pipeline.js:

    uniform float uTime;   // <-- declared, passed via shared.uTime,
    ...                    //     but NEVER used to move anything

Every mesh in the world already receives uTime every frame and you
never spend it. That means you can add VERTEX WIND SWAY to the whole
forest for ZERO extra draw calls, ZERO CPU cost, ZERO allocations —
the GPU is already running this shader.

---------------------------------------------------------------------
UPGRADE 1 — THE WIND MACRO (do this first)
---------------------------------------------------------------------
In makeInkMaterial, add one option:

    const m = new THREE.ShaderMaterial({ ...
      uniforms: { ..., uSway: { value: opts.sway ?? 0.0 }, ... },
    });

In inkVert, after `vec3 transformed = position;` add:

    #ifdef USE_INSTANCING
      ... (existing instance code) ...
    #endif
    // biro wind: gentle sway, stronger higher up, phase varies by
    // world position so no two plants ever move in sync
    if (uSway > 0.0) {
      vec3 wp = (modelMatrix * vec4(transformed, 1.0)).xyz;
      float ph = wp.x * 0.35 + wp.z * 0.27;
      float hFac = smoothstep(0.0, 7.0, transformed.y);
      transformed.x += sin(uTime * 1.3 + ph) * 0.09 * uSway * hFac;
      transformed.z += cos(uTime * 1.1 + ph * 1.3) * 0.06 * uSway * hFac;
    }

(Builders pass { sway: 1.0 } on FOLIAGE materials only — trunks and
buildings stay rigid, which is physically right and visually stable.)

Wind budget by category (uSway value):
  bamboo leaf fans & tufts ....... 1.4
  giant grass fronds ............. 1.8
  fern clusters .................. 1.2
  hanging moss strands ........... 1.6
  lantern hangers ................ 0.8
  pine/conifer skirts ............ 0.35  (subtle or they pulse)
  canopies (leaf spheres) ........ 0.25
  trails, rocks, structures ...... 0     (never)
Never sway colliders' visual shells beyond ~10cm — hatching is
world-anchored so lines stay put while silhouettes breathe: that
contrast is exactly the hand-drawn-on-a-breeze look.

UPGRADE 2 — GUST WAVES (the flagship effect)
--------------------------------------------
Add shared.uWind = { value: 1.0 } and multiply uSway displacement
by it. Then animate ONCE per frame (in your game loop, 1 line):

    shared.uWind.value =
      1.0 + 1.6 * Math.max(0, Math.sin(t * 0.13) - 0.82) * 5.5;

Every ~48s a gust rolls across the whole forest: culms lean, fronds
lift, lanterns swing, it fades. Players will screenshot it. Cost:
one sin() per frame on CPU + existing shader math.

---------------------------------------------------------------------
CPU ANIMATIONS — THE L.animated BUDGET
---------------------------------------------------------------------
Your L.animated pattern (fish, embers) is the right tool for ACTORS.
Rules to keep it cheap:
  - Budget: <= 60 animated entries total, <= 120 meshes moved.
  - NEVER allocate inside update(): no `new THREE.Vector3()` per
    frame (your fish/ember updates already do this correctly —
    keep the discipline).
  - Toggle .visible instead of fading (no alpha in the ink
    pipeline anyway — the fish already does this: correct).
  - Early-out by distance: skip the math when the player is far:

      update: (t, playerPos) => {
        if (this._far(playerPos)) return;   // squared-dist check
        ...
      }

  - Quality gate: at quality 'low', drop tier-3 actors (birds,
    butterflies, falling leaves) — check localStorage flag once.

---------------------------------------------------------------------
WHAT NOT TO ANIMATE (learned the hard way by everyone)
---------------------------------------------------------------------
- Do not animate world-anchored hatching frequency — crawl ruins
  the illusion (you already solved this with pow2 LOD — protect it).
- Do not animate colliders (visual sway != physics sway; the match
  error reads as "hitboxes are lies").
- Do not add per-frame material.uniforms writes for static props —
  uSway lives in the shader, not in JS loops.
- Do not animate more than ~2% of world meshes on CPU. 2% of this
  map ≈ 100 meshes — your budget above.

FINAL NUMBERS (aim)
-------------------
  Shader-swayed material instances:  ~10 (shared per category)
  CPU actor entries:                 <= 60
  Allocations per frame:             0 (scratch vectors at module scope)
  Added draw calls:                  0 (sway) + ~30 (new actors, merged)
  Target frame cost:                 < 0.4ms on mid GPU at 'high'
